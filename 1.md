Le premier chargement calcule chaque Gold complète une seule fois, l’écrit dans Iceberg, puis relit Iceberg pour construire Hive. Il ne faut ni utiliser computedGoldImpacted, ni rechercher des segments voisins lors de ce premier chargement.
1. Création et premier chargement
from pyspark.sql import functions as F


# À adapter uniquement si tes catalogues/databases portent d'autres noms
ICEBERG_RESOLVED = "catalog.gold.location_segments_resolved"
ICEBERG_UNRESOLVED = "catalog.gold.location_segments_unresolved"

HIVE_RESOLVED = "gold_public.location_segments_resolved"
HIVE_UNRESOLVED = "gold_public.location_segments_unresolved"


spark.sql("CREATE NAMESPACE IF NOT EXISTS catalog.gold")
spark.sql("CREATE DATABASE IF NOT EXISTS gold_public")
Fonctions génériques :
def add_entity_bucket(df, bucket_count):
    """
    bucket_count doit être une puissance de 2 :
    128, 256, 512, 1024, 2048, 4096...
    """

    if bucket_count <= 0 or bucket_count & (bucket_count - 1) != 0:
        raise ValueError("bucket_count doit être une puissance de 2")

    return (
        df
        .drop("entity_bucket")
        .withColumn(
            "entity_bucket",
            F.expr(
                f"CAST(xxhash64(entity_key) & {bucket_count - 1} AS INT)"
            )
        )
    )


def create_empty_iceberg_table(
    df,
    table_name,
    bucket_count,
    temporary_view
):
    """
    Crée la table Iceberg vide avec exactement le schéma du DataFrame Gold.
    """

    df.limit(0).createOrReplaceTempView(temporary_view)

    spark.sql(f"""
        CREATE TABLE {table_name}
        USING iceberg
        PARTITIONED BY (bucket({bucket_count}, entity_key))
        TBLPROPERTIES (
            'format-version' = '2',
            'write.format.default' = 'parquet',
            'write.distribution-mode' = 'hash',
            'write.target-file-size-bytes' = '536870912'
        )
        AS
        SELECT *
        FROM {temporary_view}
    """)

    spark.catalog.dropTempView(temporary_view)


def create_empty_hive_table(df, table_name):
    """
    Crée une vraie table Hive/ORC dans le Hive Metastore.
    entity_bucket est une partition Hive explicite.
    """

    (
        df.limit(0)
        .write
        .format("orc")
        .option("compression", "snappy")
        .partitionBy("entity_bucket")
        .mode("error")
        .saveAsTable(table_name)
    )


def publish_hive_first_load(
    iceberg_table,
    hive_table,
    bucket_count,
    write_partitions
):
    """
    Relit le snapshot Iceberg validé et construit la table Hive.
    repartitionByRange permet de répartir un gros bucket sur plusieurs tâches.
    """

    hive_df = add_entity_bucket(
        spark.table(iceberg_table),
        bucket_count
    )

    create_empty_hive_table(hive_df, hive_table)

    target_columns = spark.table(hive_table).columns

    (
        hive_df
        .repartitionByRange(
            write_partitions,
            "entity_bucket",
            "entity_key"
        )
        .sortWithinPartitions(
            "entity_bucket",
            "entity_key"
        )
        .select(*target_columns)
        .write
        .mode("append")
        .insertInto(hive_table)
    )


def initial_load_pair(
    gold_full_df,
    iceberg_table,
    hive_table,
    bucket_count,
    write_partitions,
    temporary_view
):
    """
    Premier chargement d'une population :
    1. création de l'Iceberg vide ;
    2. écriture complète dans Iceberg ;
    3. création et alimentation de Hive depuis Iceberg.
    """

    if gold_full_df.filter(F.col("entity_key").isNull()).limit(1).count() > 0:
        raise ValueError("La Gold contient au moins un entity_key NULL")

    create_empty_iceberg_table(
        df=gold_full_df,
        table_name=iceberg_table,
        bucket_count=bucket_count,
        temporary_view=temporary_view
    )

    # Première matérialisation complète.
    # Le pipeline Gold est exécuté une seule fois ici.
    gold_full_df.writeTo(iceberg_table).append()

    # La publication Hive repart du snapshot Iceberg déjà matérialisé.
    publish_hive_first_load(
        iceberg_table=iceberg_table,
        hive_table=hive_table,
        bucket_count=bucket_count,
        write_partitions=write_partitions
    )
2. Lancement concret
J’utilise bien ton bucket 128 pour les résolus. Pour les non résolus, je pars sur 4096 buckets, sans partition mensuelle : la requête comportera obligatoirement entity_key, et la plage de dates restera un filtre obligatoire.
# Ce sont tes deux DataFrames finaux calculés sur TOUT l'historique Silver.
# Ils ne doivent pas être computedGoldImpacted.
gold_resolved_full = computed_gold_resolved
gold_unresolved_full = computed_gold_unresolved
Charge d’abord les résolus :
initial_load_pair(
    gold_full_df=gold_resolved_full,
    iceberg_table=ICEBERG_RESOLVED,
    hive_table=HIVE_RESOLVED,
    bucket_count=128,
    write_partitions=512,
    temporary_view="tmp_gold_resolved_schema"
)
Puis, dans un second job ou après libération des caches, les non résolus :
initial_load_pair(
    gold_full_df=gold_unresolved_full,
    iceberg_table=ICEBERG_UNRESOLVED,
    hive_table=HIVE_UNRESOLVED,
    bucket_count=4096,
    write_partitions=8192,
    temporary_view="tmp_gold_unresolved_schema"
)
Ne lance pas les deux simultanément. Et surtout, ne fais pas de coalesce() avant l’écriture des non résolus : repartitionByRange(8192, entity_bucket, entity_key) est précisément là pour éviter de recréer les partitions Spark gigantesques que DataFlint t’a signalées.
3. Ce que fait exactement ce premier chargement
flowchart TD
    S["Silver historique complet"] --> G["Calcul Gold complet"]
    G --> R["Gold resolved"]
    G --> U["Gold unresolved"]
    R --> RI["Iceberg resolved"]
    RI --> RH["Hive resolved"]
    U --> UI["Iceberg unresolved"]
    UI --> UH["Hive unresolved"]
À ce stade :
aucune lecture de l’ancienne Gold ;
aucun calcul de voisin gauche ou droit ;
aucun MERGE;
aucun computedGoldImpacted;
le checkpoint initial n’est validé qu’après la réussite de la publication Hive.
Iceberg prend officiellement en charge le partitionnement caché bucket(N, entity_key) et les créations CTAS. Pour les chargements incrémentaux suivants, MERGE INTO permettra de ne réécrire que les fichiers concernés. Documentation Iceberg DDL⁠� et écritures Iceberg⁠�. La création Hive/ORC avec saveAsTable enregistre bien la table dans le Hive Metastore. Documentation Spark/Hive⁠�.
